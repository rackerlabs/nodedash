# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

nodedash is a web UI for hardware administration of OpenStack Ironic bare metal nodes. It is a React SPA plus a
Fastify backend-for-frontend (BFF). Users sign in through Keystone WebSSO, pick a region, and the BFF calls that
region's Ironic, found in the Keystone service catalog, with the user's own token.

## Layout

| Path | What lives there |
| --- | --- |
| `apps/bff` | Fastify BFF: WebSSO, encrypted cookie sessions, Keystone and Ironic clients, `/api` routes |
| `apps/web` | React SPA (Vite, React Query, react-router, Tailwind); `src/mocks` is the MSW mock wiring |
| `packages/shared` | Schemas and rules both sides must agree on: API types, microversions, node rules |
| `packages/mock` | In-memory fake Keystone/Ironic backend and fixtures, used by mock mode and tests |
| `e2e` | Playwright tests, run against the mock backend |
| `charts/nodedash` | Helm chart, released with the image |
| `docs/ironic-api-gaps.md` | Ironic endpoints the UI needs that upstream does not have yet |

## Commands

```bash
npm ci
npm run dev:mock    # SPA with the mock backend, no deployment needed
npm run dev         # BFF + Vite against a real region (reads apps/bff/.env)
npm run typecheck
npm test            # Vitest
npm run test:e2e    # Playwright, mock backend
npm run build
helm lint charts/nodedash -f charts/nodedash/ci/test-values.yaml
docker build -t nodedash .
```

Run `npm run typecheck`, `npm test` and `npm run test:e2e` before calling a change done. Change the chart, and
`helm lint` and `helm template` it with `ci/test-values.yaml` too.

## Design rules that are easy to break

- **The BFF is stateless.** Per-user state lives only in the encrypted `HttpOnly` session cookie
  (`@fastify/secure-session`, keys from `SESSION_KEYS`). Do not add per-user server-side caches or stores. Any
  replica must be able to serve any request. Process-wide caches are fine only for data that is the same for every
  user (Ironic version documents, domain names).
- **Tokens never reach the browser's JavaScript.** Keystone tokens stay in the cookie. Responses must not include
  them, and Ironic responses pass through `redactSecrets` before they are returned.
- **The page and `/api` share one origin.** The cookie and the WebSSO callback depend on it, which is why the image
  serves the SPA from the BFF.
- **Rules live in `packages/shared`**, so the mock and the real path cannot drift. Put a rule there, not in a
  component or a route.
- **Gate Ironic features on the negotiated microversion** (`CAPABILITY_MICROVERSIONS`), not on assumptions about the
  deployment.
- **Mock code never ships.** The mock backend, its fixtures and MSW load only behind the inline `VITE_MOCK` check
  in `apps/web/src/main.tsx`, so a production build drops them. Keep it that way.
- **Mock fidelity.** The mock should behave like real Keystone and Ironic, including header names, status codes and
  error shapes. Check a new upstream behaviour against the API reference or a live service. Do not copy what the
  mock already does: a wrong header name once passed every test and failed only against real Ironic.
- **Branding is configuration.** The name, tagline and logo come from `BRAND_*` on the BFF, via the session. Do not
  hard-code a product or company name in the UI.

## Conventions

- **License header.** Every source file starts with the Apache 2.0 header naming "Copyright <year> Rackspace
  Technology." Use the year the file is created. Copy the header from an existing file of the same type:
  - `/* */` for TypeScript, JavaScript and CSS;
  - `<!-- -->` in HTML, after the doctype;
  - `#` for YAML, the Dockerfile and `.env.example`;
  - `{{- /* */ -}}` in Helm templates.

  JSON, Markdown and lockfiles have none. `apps/web/public-mock/mockServiceWorker.js` is generated by MSW and keeps
  MSW's own license; do not add our header to it.
- **Third-party code.** `apps/web/src/components/ui/*` derives from shadcn/ui (MIT), credited in `NOTICE`. Credit any
  other copied or adapted code there too, with its license text.
- **No real data in fixtures, tests or docs.** Use placeholders:
  - people: `example-user@example.com`;
  - hosts: `*.example.com` or `*.example.invalid`;
  - IP addresses: `192.0.2.0/24`;
  - sites: made-up names such as `north1` or `east2`;
  - identity provider: "Corp SSO".

  No real names, hostnames, data-centre codes, credentials or customer data.
- **Secrets** come from the environment only (`SESSION_KEYS`). Never commit a `.env` file or a real key.
- **Match the surrounding code:** naming, comment density and idiom. Comments explain why, not what.

## Releases

Pushing a `v*` tag runs CI to build and push the image to `ghcr.io/rackerlabs/nodedash` and to release the Helm chart at
the same version, pinned to that image's digest, to `oci://ghcr.io/rackerlabs/charts`. Pull requests build both but
publish nothing.
